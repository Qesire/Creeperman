六年均完成排序检查：归一化逆序为 0、同年重复为 0、正则非法为 0。

“正则有效”仅指通过附带 `HOST_RE`。跨年相同 hostname 分别计数，合计是 hostname-year 数而不是跨年唯一网站数。“无英语权重”包括 JSON 中没有 `eng` 行的 TLD，不一定意味着该 TLD 完全没有出现在 JSON 中。

据初算总量 **76,430,446.4446 EED**，1% 的精确增量是 **764,304.464446 EED**，2% 为 **1,528,608.928892 EED**。由于该模型贡献以四位小数为最小计量精度，对应至少达到 **764,304.4645** 与 **1,528,608.9289 EED**。门槛针对六年核心合计，不要求每年分别增长 1% 或 2%。

这两个门槛仅对当前原始六年文件、当前模型及核心范围成立。真正提交时须基于组织者最新确认基线、合并去重后的合格新增和适用扩展年规则重新计算。阈值比较使用未舍入数值；不能把向下四舍五入的数当作达标依据。

## 统计方法与核查

复现脚本见 [audit_baseline.py](../audit/audit_baseline.py)。它引用任务包计算器的 `strip().lower()`、`HOST_RE` 和模型加载函数，以二进制流读取每行并计算 SHA-256；完整检查归一化字典序后进行相邻去重，再按 TLD 计数并用精确 `Decimal` 聚合。排序成立时，这一去重方法与全量 `set` 等价；若发现逆序，脚本拒绝报告该年的唯一数与 EED，需先外部排序再统计。

另取 1996 年文件前 100,000 行与原始 `calculate()` 对照：两者唯一记录数均为 100,000、正则非法数均为 0、EED 均为 **58,856.9428**，断言全部通过。这是排序前缀上的算法一致性检查，不是随机抽样的网站质量审计。

精简机器结果与输入指纹见 [baseline_summary.json](../audit/baseline_summary.json)；实现探针及样本对照结果见 [calculator_checks.json](../audit/calculator_checks.json)。完整 TLD 分布可用脚本重新生成。

```powershell
# Python 3.10+，无需第三方包；在本仓库根目录运行。
# 第一个参数须指向保留原目录结构的本地任务包。
python audit/audit_baseline.py "G:\1996-2001KnowledgeDiscoveryCompetition" "./work/baseline-recheck"
```

脚本固定读取 `merge261121-3` 六年清单；其他基线版本须显式调整输入版本并重新记录指纹。输出放到第二个参数指定目录；不会改写原始年度文件，也不调用网络。它是文件统计复现工具，不是完整的竞赛验收器。

## 计算器实际做了什么

| 源码位置 | 行为 | 边界 |
|---|---|---|
| `equivalent_english_domains.py` 16—20 行 | ASCII hostname 正则 | 不是 IANA/历史 TLD 白名单，也不识别网站证据 |
| 46—60 行 | 读取非空 TLD 的 `eng` 百分比并除以 100 | 模型无英语权重时贡献为零 |
| 63—70 行 | 每行去首尾空白、转小写、集合去重 | 不去掉 `www.`、URL scheme、末尾点或路径；大文件集合占用较多内存 |
| 73—100 行 | 正则检查、最右 TLD 分组、Decimal 求和 | `a.co.uk` 用 `.uk` 权重，不做可注册域归并 |
| 104—123 行 | 单文件总量与覆盖率输出 | 不计算逐年基线差集、官方验收结果或时间分数 |

模型包含 1,330 个非空不同 TLD 字符串，1,306 个英语权重。没有重复的英语权重键，所有英语权重均位于 `[0,1]`。JSON 是本任务的固定计分依据，不是当前根区合法性清单。

## 真实基线中的完整性问题

| 本地文件位置 | 值 | 判断 |
|---|---|---|
| `1996.txt` 第 1,754,759 行 | `www.com` | 正则会接受且计分，任务书 XIV 的裸 `www.<单标签>` 规则要求隔离 |
| `1996.txt` 第 1,777,616 行 | `www.de` | 同上 |
| `1996.txt` 第 1,962,079 行 | `www.net` | 同上 |
| `1996.txt` 第 598,096 行 | `gis.joensuu.fi.joensuu.fi` | 存在重复终端后缀模式，应核查原记录、抽取过程与确切证据；本次未裁定其真实性 |

合成输入也确认，`www.com` 和 `host.example.org.example.org` 会分别得到 0.6321 和 0.7101 EED。探针只用于说明代码行为，没有历史证据，不能作为新增记录提交。`example.thisisnotatld` 会通过正则但没有英语权重；URL、路径、端口、IP 和下划线输入被正则拒绝。末级只允许字母，因此 punycode TLD 如 `example.xn--p1ai` 也不被当前脚本接受，不能悄悄换用另一种规范化规则后仍宣称口径一致。

这些实例证明，“正则非法数为零”不能解释为数据已经清洁。本次未进行全量语义清洗或网站证据审查；修复结果应另建可审计基线版本，并对所有比较使用一致口径。旧 `example_1998_results/summary.json` 的 698,408.2027 EED 属于 `merged260802-2`，不适用于本次当前基线。
