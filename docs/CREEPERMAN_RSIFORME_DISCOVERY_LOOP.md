# Creeperman × RSIforme：从成功获取路径到持续净增

2026-11-28。竞赛结果依据 Creeperman `6831270`；本文定义两仓接合和执行顺序。在线策略加载、路径反馈及真实目录运行的最新状态见 [本轮实现](LIVE_DISCOVERY_2026-11-28.md)，具体种子见 [起始点分析](DISCOVERY_SEEDS_2026-11-28.md)。邮件、数据申请继续暂停。已完成的 WebBase、DMOZ 版次和旧池交集保留其完成状态。

## 1. 已经得到的正面结论

**当前最有实证依据的方法，是追索有年代依据的历史版本，恢复原件后批量连接年度基线，直接裁决其中的新记录。** RSIforme 应把这类成功获取过程变成可复用的操作，并根据后续批次的真实贡献选择下一步。

最近一轮沿出版方 `rdf.dmoz.org/rdf/archive/` 找到旧版本，取得 2000/2001 年生成、2006/2010 年保存的文件。四版联合 1,525,310 个主机年度，经基线与既有台账差集，新增 100 项、63.2063 EED；其中 99 项来自 2000 Kids，1 项来自 2001 主目录。累计为 155 项、100.9875 EED，组织者尚未复核。[原件和裁决](DMOZ_ARCHIVE_EDITIONS_2026-11-27.md)

可迁移的是“出版关系与版本路径 → 有日期的原件 → 批量年度裁决”这段操作。已消费的 DMOZ 文件不再产生新奖励。资料发现可以查找后来保存的早期原件；网站年度仍由原件、具体条目和证据规则固定。原件生成年、档案保存年和目标网站证据年分别记录。

WebBase 全部 118,142,155 个 URL 节点贡献 0 EED，说明该版名单已经耗尽；这不能替代其他原件、年份或提取操作的结果。8,677 次 HTML 观察中 40 次正文复用，只测得缓存节省，未报告完整的外链净收益。[现有实测](ARCHIVE_ENGINEERING_2026-11-27.md)

这里的“稳定增量”指：**同一操作在相互独立、此前未消费的批次上重复取得正净收益，并且还有可定位的未处理库存。** 报告覆盖范围、批次数、收益与成本的分布；有限历史材料不支持永久或任意固定速率的承诺。

## 2. 三条可执行的种子操作

这些是操作模板；每次实例化必须绑定真实对象及未消费范围。

| 操作 | 输入与动作 | 产出和下一步 |
|---|---|---|
| **追索出版方历史版次** | 从已经观察到的发行页、版本目录、文件清单或引用，访问对应版次、镜像和保存副本；核对内部生成日期、发布关系及字节完整性 | 同期权威目录或其他可裁决原件进入年度差集。新版本关系继续回流资料前沿。最新 DMOZ 批次是成功实例 |
| **连接原件、URL 和年份** | 对已经取得的网页包、CD、镜像或原始记录，先读清单和映射；为差集中的记录恢复正文、原 URL、日期及转换谱系 | 形成具体年度证据包，已有适格原件直接裁决。WebKB 的原始 HTML、Linux Gazette 的同期 WWW 目录已有本地正贡献；不要求它们先经过逐主机在线查询 |
| **消费历史正文的未提取信息** | 先查覆盖账本，只处理未执行当前操作的页面版本；解析实际超链接、资源引用、锚文本及资料链接 | 资料链接引出新原件；普通目标链接进入缺年补证队列。源主机已在基线不阻断展开；目标仍需独立网站证据。本分支的本地稳定产率待完整收据确定 |

第一条不重新穷举已经查明的 DMOZ 同一路径。第二条不能把导入工具生成的 HTTP 头、日期和 URL 当作原始事务。第三条优先使用本地已有字节；重复正文仍按实际 original URL、base 和记录身份解析，不能只凭正文摘要合并年度上下文。

## 3. 把发现操作接成反馈闭环

调度单元取 **来源 × 年份范围 × 操作 × 原始采集家族**，任务另绑定原件版本和记录范围。这样同一来源的 2000 与 2001 年、名单解析与正文提取可以获得不同评价；同源镜像共享祖源，不伪装成新的独立成功样本。

设冻结基线为 B，本轮开始的已裁决集合为 A，动作 a 最终得到的合格年度键为 V(a)。唯一生产贡献为：

\[
g(a)=\sum_{x\in V(a)\setminus(B\cup A)}w(x).
\]

各动作的贡献按全局键去重。资料页、下载和解析可以先没有即时收益：保留父子动作关系，待后代证据完成裁决，再将成功路径用于更新排序特征。路径上的每个节点可以获得学习信号，但最终 EED 只结算一次。文件数、候选数和条件权重上界是过程观测，不替代 g(a)。

执行循环：

1. 从现有库存和前沿列出未消费任务，绑定版本、年份语义、操作实现与预算；复用已有文件。
2. 排序选择依赖已满足的任务，保留一定探索机会给尚无完整结果的来源家族。
3. 由现有执行器获取或解析，保存字节、locator、请求及成本；新发现边回送前沿。
4. 对真实年度观测做 B、A 差集；已有证据直接裁决，明确缺证者进入有界补证。
5. 结算净增，将完整结果和成功路径回送调度；更新剩余范围。
6. 处理完的范围关闭。后续只因新原件、新版本、新记录角色或新提取操作重开；429、503、截断等保留未完成状态，不当作完整零收益。

优先级使用已完成批次的净 EED、全部成本、剩余可处理范围和估计不确定性。来源会耗竭，收益必须随全局已发现集合更新，不能用一个早期高收益常数永久排序。原件数有限且可枚举时直接记剩余清单；未知覆盖时才估计未见量。

## 4. 两仓的最小接合

Creeperman 负责原件、出处、执行、裁决与生产结算；RSIforme 负责生成和比较排序策略，保存策略及反馈。规则、基线、权重和可信审核结果由评估端固定，策略不能自行写入“合格”。

`source_frontier.Frontier.choose()`、`source_pages.PageFrontier.run/reuse_queued` 已调用 `discovery_policy.LivePolicy`；未加载策略时保持旧排序。已加载策略保存选择特征和策略摘要，保留来源探索，并从明确完整的裁决范围学习 URL、锚文本、上下文与成功祖先路径。目录解析成功不等于已完成证据范围。[在线实现与命令](LIVE_DISCOVERY_2026-11-28.md)

RSIforme 的 [examples/creeperman_replay](https://github.com/Qesire/RSIforme/tree/main/examples/creeperman_replay) 保留固定 epoch 的多维预算重放；新增 `export_live.py` 把显式启动先验或已确认 release 的排序导出给真实前沿。后者核对原候选、search、confirmation、profile、epoch 和封存证据；固定 epoch 的重放有效，不等于新在线环境有效。探索与路径衰减仍标为未验证扩展。

生产端先导入可信累计 A，再导入独立审核的 settle 输出及真实成本、节点和已完成范围，实施全局唯一年度键奖励。合成合同测试已证明后代反馈会改变下一次实际前沿选择；本轮真实元数据采集尚无裁决反馈，没有启动模型自主迭代。生产收据到 recorded epoch 的自动整理仍未完成。

### 冻结比较与生产增长分开

一个评价 epoch 固定 B、开始时的 A、资料快照、规则、权重、预算和 evaluator 版本。策略在相同上下文比较；新资料或 A 改变时新建 epoch。历史重放可复现“55 项到 155 项”的 63.2063 EED，但这不再次增加当前生产台账。跨 epoch 原始分数不直接排名。

RSIforme 的 confirmation 是在同一冻结任务上新执行一次，不自动构成未见来源验证。评价可复现后，应另建按原始采集家族或出版版本分组的任务，在其中同时比较现行策略和挑战策略；不要随机拆散同一原件的页面来声称跨来源稳定。新任务及真实生产结果分别保留。

真实前沿排序及审核后反馈已经接入；还需将有完整范围、成本和逐项证据的生产回执导出为 recorded epoch，才能用实际材料比较策略。未知动作先执行并留证，不能用离线重放替它预测出真实收益。

## 5. 可信奖励与数据契约

`core.audit_binding()` 已绑定六年基线、权重与规范化身份。`parquet_difference.compare()` 已扣 B 和指定审核台账，输出的 `unsettled_eed_ceiling` 仍是条件上界；跨来源行不能相加作联合收益。[差集实现](../src/creeperman/parquet_difference.py)

`settle()` 核对已裁决记录的 authority、rule_version、确切主机年度和原件摘要；它是核算器，不能自行判断网页证据是否成立。并且它只扣 B，不扣旧累计 A。现有在线反馈先绑定完整累计 A，再对 settle 的年度结果按 (hostname,year) 全局去重；同一 SQLite 账本通过事务和唯一键防止重复奖励。这是反馈台账，不是跨多个独立数据库的分布式提交协议。正式生产导出仍需当前 A 的独立核对。[结算实现](../src/creeperman/settle.py)

接合必须保留以下关系：

| 对象 | 必须绑定的内容 |
|---|---|
| epoch | 基线、旧台账、规则、模型及 evaluator 摘要；数据为 recorded 或 synthetic_fixture；预算 |
| action | 来源、原件身份、locator、依赖、可见特征、成本上界、来源采集家族及操作版本 |
| outcome | complete / incomplete / unobserved；实际成本；收据位置与摘要；实际揭示的子任务 |
| qualified record | exact hostname、year、evidence_id、证据定位与摘要、可信审核状态 |
| coverage | `input_sha256`、`operator_revision`、`record_locator`、`original_url`、`capture_or_edition`；确定性生成 coverage_id，保留相同正文的不同观察上下文 |

现有 discovery job 的 version 为 `exact-host-v1`，它是规范化版本，不是提取器版本。接入新的提取操作时增加实现指纹并由执行端核对实际运行代码；否则相同输入可能错误复用旧操作的完成状态。资料和真实主机名单留在私有执行目录，公共仓库只保存代码、契约及已公布汇总。

冻结材料只需携带本轮候选年度键全集 K 与 B、A 的交集，不必把 1.4 亿行基线复制到重放文件。这个作用域投影由可信准备端通过完整基线和既有账本计算，另绑定全量原文件摘要；策略不能提供或删改排除集。冻结文件保证比较对象一致，不替代原始证据审核。

## 6. 国际方法在这里各承担什么

- **ACHE，WWW 2007**：保存成功发现路径，从 URL、锚文本及周边文本学习链接特征，再重排前沿；允许多步之后才得到收益。这里将目标从相关表单换成最终可裁决的新年度证据，保留路径学习机制，不迁移其论文中的提升倍数。[原论文](https://archives.iw3c2.org/www2007/papers/paper429.pdf)
- **Good-UCB，JMLR 2013**：目标是发现未见的有价值对象，重复命中不增加收益，选择依据随剩余未见质量变化。这里借鉴耗竭与跨源去重；本文的定向、变成本、互相重叠批次不满足其固定分布抽样及部分理论所需的不交叠条件，先用可解释的批次收益策略，不宣称继承后悔界。[原论文](https://www.jmlr.org/papers/volume14/bubeck13a/bubeck13a.pdf)
- **AlphaEvolve**：用执行和 evaluator 反馈改进算法，保留候选程序与结果。这里先演化有约束的排序策略；网站证据仍由固定规则与独立裁决形成，模型自述不进入 reward。[技术报告](https://arxiv.org/html/2506.13131v1)
- **ALE / DECam**：编码 Agent 改进 finder，固定评价比较程序；独立 conveyor 用当前最好程序扫描新的天空分区，候选再经过新颖性和确认检查。这与本项目“改进发现操作、消费新的档案批次、独立结算”直接对应。其私有数据和运行环境不随源码公开，作者成绩不作为本项目实测。[固定版本 README](https://github.com/huangzesen/decam-rsi-pipeline/blob/572082bab9d18396b0f1ce607046baeed32dd159/README.md)
- **ArchiveTeam**：项目专用对象枚举、依赖发现回送、WARC 持久化后确认完成，适合复制到资料批次执行。[Cohost 流水线](https://github.com/ArchiveTeam/cohost-grab/blob/441b1c22692df19d193e3e67a785cc91aa584c6e/pipeline.py) · [发现脚本](https://github.com/ArchiveTeam/cohost-grab/blob/441b1c22692df19d193e3e67a785cc91aa584c6e/cohost.lua)
- **Arquivo / Archive95**：回溯历史依靠接收旧载体、恢复 URL 映射与日期、区分原件和重建字段。它们为第二条操作提供实际工程参照。[Arquivo 历史集合整合](https://sobre.arquivo.pt/wp-content/uploads/creating-a-billion-scale-searchable-web-archive-1.pdf) · [PC Press 光盘恢复](https://archive95.net/sources/pcpress)

## 7. 执行交接

先把现有私有收据整理成 recorded epoch：包含成功路径、完整零新增批次和明确未完成批次，保留各自成本；用历史 A 复现历史收益。缺失成本先从原请求与执行日志补回，不填写零成本；已公布汇总不能替代逐项 outcome。完成桥接重放后，从已有前沿挑选有 locator、有未消费范围的下一批实例，优先采用前三条操作。每批结束都补齐年度净收益、总成本和剩余库存，再更新策略。

不重新跑已耗尽来源来制造反馈。现有材料没有该操作的完整记录时，先核对实际覆盖；已处理部分复用结果，未处理部分才执行。全球 worker 承接这些独立批次，提供者预算统一管理。

验收分开报告：重放是否遵守依赖、预算和唯一计分；新实例是否产生真实净 EED；同一操作能否在独立未消费批次重复正收益且仍有可定位库存。当前累计分数保持 155 项、100.9875 EED，桥接代码与历史重放本身不增加竞赛贡献。
