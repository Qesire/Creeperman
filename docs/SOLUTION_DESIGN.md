# Creeperman 方案：以可验收的历史证据供给推进竞赛

设计日期：2026-11-24（UTC+8）。规则依据为本仓库 `b2c0bae0fa607c306126f2197ed16c652a3af338` 对任务包的解读，主规则版本为 2026-10-20，比较基线为 `merge261121-3`。本方案保留[来源核查记录](SOURCES_AND_AUDIT.md)对 WHOIS 条款、扩展年度分母等事项的限定。

## 全过程的解释依据

当前来源优先级以[档案起源与剩余发现](ARCHIVE_ORIGINS_AND_RESIDUAL_FRONTIER.md)为准：用户已说明 WebBase 2001 几乎读入、已使用的 IA 主体来源几乎读完。先找有实际保存依据的剩余历史观察，再绑定成熟组件。具体归档与全球执行机制见[研究复核后的方案](EVIDENCE_LED_REDESIGN.md)及[源码审计](OPEN_SOURCE_COMPONENT_AUDIT.md)；此前探针保留为历史观察，本轮未新增测试。

最新[发现与取证流水线](DISCOVERY_AND_VERIFICATION_PIPELINE.md)进一步固定六类对象、具体历史文本材料、CDX witness 选择与查询完整性、回放实际年份及提供者预算。资料发现可以直接产生合格证据；在线验证仅补缺口。Usenet、同期邮件和明确版本的论文成为新的优先来源契约工作；已有大源仍只有明确缺口才重开。

后续[论文机制与发现操作](LITERATURE_AND_DISCOVERY_OPERATORS.md)增加引用提取、语义反搜与来源集合追溯，明确每条路径的输入、输出和停止条件。CMU 原版、派生图集、NCSA 镜像及晚期目录分别记契约；后期线索不倒填早年证据。路由按具体收藏年代和访问能力筛选，负缓存到期只恢复准入资格，原件/回放/分析摘要按字节域分开。门槛级残余供给仍未证明。

先阅读[全过程与剩余发现](PROCESS_AND_RESIDUAL_DISCOVERY.md)，再按本文选择具体来源与组件。该文定义来源/资料待办与候选/缺年验证待办：直接计分按基线求差，资料展开按来源版本及操作状态去重。批量索引仍是适合明确材料的处理方式；它不再构成“尚有大型未读主索引”的供给假设。

## 1. 首先要取得什么结果

首个里程碑是：**用实际可取得的历史资料，证明有足够的基线外、可逐年举证的 hostname-year，并测出把它们转为提交结果的成本。** 达到这个里程碑后，再扩大获取与处理。

当前主线为“确定未消费的历史观察、恢复身份时间、形成合格年度差集”，辅线为已有候选定向补证。优先调查公开抓取索引之外的同期业务记录、独立采集与交存；已有正文或索引只有明确的处理缺口才重新展开。当前尚未证明有足够材料跨过 1% 门槛，不能以增加查询工具或全球节点替代供给判断。

| 需要跨过的门槛 | 要回答的问题 | 首轮决定性证据 |
|---|---|---|
| 来源剩余容量 | 目标年份还有多少可取得、与基线不重叠的记录？ | 全量小来源或可说明抽样边界的来源差集；可继续获取的真实目录 |
| 身份与年份 | 原始记录是否支持这个确切 hostname 在这一年出现网站？ | 原始 URL、观测时间、网站语义及可回查定位 |
| 兑现成本 | 已确认新增能否在预算内累计到门槛？ | 新增 EED/墙钟小时、EED/请求、EED/GB、人工复核分钟 |
| 完整提交 | 增量经最新基线合并后，是否满足规则及包装要求？ | 确定性年度文件、差集、证据账本、复现代码和完整 7z 包 |

前三项决定方案能产生多少贡献；最后一项决定贡献何时能成为完整提交。所有来源试验同时记录未知可注册域覆盖，避免仅由高频平台子域决定策略。

## 2. 把 1% 门槛换算为真实数量

[当前基线审计](BASELINE_AUDIT.md)记录 140,073,629 个 hostname-year，初算总量为 76,430,446.4446 EED。最低 1% 和建议 2% 对应：

- 1%：未舍入值 `764,304.464446`，按四位小数贡献精度至少 `764,304.4645 EED`。
- 2%：未舍入值 `1,528,608.928892`，至少 `1,528,608.9289 EED`。

这只是当前基线与固定模型下的计划门槛；正式提交按组织者最新确认基线重新求差。基线语义清理应另建版本，再对两侧使用一致口径。

| 新增记录平均权重 | 达到 1% 所需的合格、基线外 hostname-year |
|---:|---:|
| 1.0000（理论最高） | 764,305 |
| 0.9813（任务包 `.uk` 权重示例） | 778,870 |
| 0.6321（`.com` 示例） | 1,209,152 |
| 0.6000（工作量情景） | 1,273,841 |
| 0.1324（`.de` 示例） | 5,772,693 |

因此，来源的“数百万 URL”“几十 GB 索引”需要依次压缩为：目标年份记录、不同 exact hostname-year、合格证据记录、基线外记录、与本轮其他来源去重后的 EED。

设来源集合为 S，`V_s` 为其中已满足证据策略且去重的 `(h,y)` 集合，B 为冻结的年度基线集合。工程目标是：

```text
F(S) = Σ[(h,y) ∈ (∪s∈S V_s) \ B] w(TLD(h))
Δ(s | S) = F(S ∪ {s}) − F(S)
```

`Δ(s | S)` 是来源相对于当前已完成结果的边际贡献。对固定的来源结果集，S 扩大时新增覆盖具有递减收益；这由集合并与非负权重直接得到，支持按实际边际贡献更新来源优先级。这一覆盖函数只适用于每个来源已独立形成完整合格集合的情况；原文件与映射、revisit 与原记录等证据互补，可能使两个单独零收益来源合起来产生贡献，需要按完整证据任务评价。实际结果未知时，先核定可观察范围，不以情景产率代替供给量。Arquivo 的 IA 收藏与 UKWA/JISC 包含 IA 派生数据，提供者数量不等于独立信息数量。

若源数据有 N 个不同目标 hostname-year，q 是“证据合格且基线外”的联合比例，这些合格新增项的条件平均权重为 w̄，则 `N × q × w̄` 可以作为有条件的工作量情景。q 直接在同一批样本上测量；不把不同总体中的“年代率、新颖率、成功率”独立相乘。

例如 w̄=0.6、q=10% 时，达到 1% 约需处理 12,738,408 个来源内不同 hostname-year。这是条件算术；不能把 10% 用作已近乎处理完的 IA/WebBase 的剩余率，也没有据此证明存在这么多可得材料。

若逐 host 查询速率为 r 次/秒，计划用 T 天达到最低门槛，平均每次请求需要兑现：

```text
g_required = 764304.464446 / (86400 × r × T)  EED/request
```

按 **r=1 次/秒的情景**，7/14/30 天分别要求约 1.2637/0.6319/0.2949 EED/request。这不是服务配额或收益预测；一次查询可返回同一 host 的多个年份，也可能完全没有新增。真实 g 必须包含空结果、重复、失败和补证成本。存在未处理的有效分片时，批量获取可以提高请求效率；同范围已经完成时，重复获取不改善发现空间。

## 3. 成熟方案给出的执行顺序

Arquivo 官方的批量访问流程是选择收藏、下载 CDXJ、筛选记录、按需取回网页；ArchiveSpark 把元数据筛选与内容派生结合并保留来源。将这一顺序用于竞赛，可以让已在基线中的记录尽早退出重复证明自身的昂贵流程。同时保留有发现价值的历史资料，按独立的展开状态提取目录、外链或检索词；不能把计分差集无条件前推到全部正文处理之前。[M1、M4；全过程与剩余发现 §5]

### 3.1 对明确存在的未处理材料：批量索引到年度差集

1. **读取来源说明与实际交付清单。** 确认年代、字段、对象范围、取得方式、数据祖源及未处理依据；资料仍有关键歧义时再定义相应核验。
2. **解析索引。** 从 `original`/`url` 提取原始 URL 的确切 hostname；从语义已确认的捕获时间取年份；保留 locator、状态、MIME 和 digest。
3. **全局归并身份键。** 按 `(exact_hostname, year)` 去重，同时保留该键的候选证据或回到原分片继续找证据的路径。
4. **与同年基线及本轮已完成结果求差。** 已有年度记录不重复计分，其他年份仍单独处理。
5. **兑现证据。** 对每个待新增键取得至少一个符合当前证据策略的真实记录。需要正文、重定向链或 revisit 原记录时定向读取；已有充分证据的索引记录直接引用其来源。
6. **计分和反馈。** 精确累计 EED，同时记录新可注册域数、成本和未完成范围。

上述步骤是直接贡献分支。来源展开分支则按“资料版本、操作、范围是否已经完成”决定是否读取；即使自身 host-year 已入基线，也可通过真实历史外链产生独立候选。

处理顺序可以由低成本索引过滤优化，但逻辑必须满足 `V(h,y)=存在至少一个合格 witness`。witness 可以是足够成立的单条记录，也可以是具有明确对应关系的文件、URL 映射和时间日志等证据包。只保留第一条索引记录、在其失败后丢弃整个 hostname-year，会遗漏同键下后续的合格捕获。可保存少量优先 witness 与来源分片定位；需要更多时重读对应分片。

### 3.2 两个必须保住的键语义

**确切主机名来自原始 URL。** Webrecorder 的官方 CDXJ 示例中，`urlkey=org,iana)/domains/example` 对应 `url=http://www.iana.org/domains/example`。SURT 键已经可能合并 `www`。Archives Unleashed 的标准 Domain Graph 也会显式删除 `www`。这些变换适合其原任务；Creeperman 应在原始 URL 层提取 hostname。[M3、M5]

**相邻聚合之后仍需全局去重。** 旧 Creeper 的 `host_year.py` 按连续 original hostname 归并。一个按 SURT 排序的流可以出现同年 `example.org/a → www.example.org/a → example.org/b`：形成三个连续组，但只有两个 hostname-year。先做局部压缩可以节省工作，最终计分必须建立在全局唯一键上。UKWA 年度 CDX 还明确标为未排序。[M2、M9]

### 3.3 证据判定按来源类型组织

| 证据类型 | 年份依据与身份依据 | 应保存和核查的内容 |
|---|---|---|
| 真实 HTTP 捕获、ARC/WARC | 实际捕获时间；原始目标 URL | 响应/资源语义、记录类型、状态、正文或可回查定位 |
| 规则认可的历史目录/host-link graph | 该版本实际观测年；明确节点身份 | 节点映射、source/destination 角色、数据生成过程、逐条定位 |
| 光盘、缓存、原始网站备份 | 抓取日志或经过核定的历史时间范围；原始 URL 映射 | 原介质哈希、映射文件、修复过程、日期不确定性 |
| DNS、注册、邮件和普通提及 | 仅作发现线索 | 用于安排后续网站核验，保存其本身真实日期语义 |

可信 host graph 的源节点与外链目标具有不同的直接观测含义。按竞赛允许的目录/图证据路线处理，保留类型；普通网页外链先成为待核候选。两者均无需被改写为“目标页 HTTP 200 捕获”。

HTTP 2xx、3xx、revisit、缺失状态及软错误页需要明确策略。首轮使用最容易解释和复核的捕获类别，同时保留其他类别的原记录供后续策略处理。当前仓库尚无组织者对所有边界情况的完整机器判定表。

时间字段至少区分 `observed_time`、`time_semantics`、`recovery_time`。Memento 的返回时间才对应返回状态；请求日期只表达希望查到的时间。若可信证据给出一个区间，保留起止边界；区间完全在同一年且网页语义成立时可作为待审核年度记录，跨年区间继续补证。该区间策略是实施建议，需要适用证据规则支持。[M6]

### 此前已完成的小来源实测：Roteiro 的容量边界

此前来源探测轮读取了完整 `Roteiro.cdxj`，解压后的 13,585,912 字节与响应对象长度一致，SHA-256 为 `0d8866492189b2509ec2981780e1df1f50e8cc9d4d618051cfaef7e725d1c8db`。统计结果为：

| 观测项 | 数量 |
|---|---:|
| 原始 CDXJ 记录 | 44,379 |
| capture 年份为 1996、状态为 200 | 44,379 |
| 明确识别的 IP URL | 184 |
| 当前 ASCII hostname 规则排除的记录 | 645 |
| 通过本次 URL/hostname 语法筛选的记录 | 43,550 |
| 上述集合的不同 exact hostname-year | 4,955 |
| HTML 200 记录 | 1,811 |
| HTML 200 的不同 exact hostname-year | 939 |

HTML 数量是当前筛选子集，不把其他 MIME 的网站证据价值直接判为零。645 条中包含末尾点等需要单独解释的形式；这些排除也不等于全部语义无效。

在“4,955 项全都基线外、证据合格、权重全为 1”的极乐观情景下，该已解析集合至多贡献 4,955 EED，约为最低提交门槛的 **0.6483%**。即使以全部 44,379 行作为直接索引路线的宽松贡献上界，也只覆盖门槛约 **5.8065%**。实际合格差集与权重会进一步改变结果；额外从正文扩展外链属于另一条来源处理路线。

因此，这个具体索引适合验证解析、身份、日期、证据定位和基线差集，并贡献小规模补充。主力来源的选择应继续依据各自的真实容量与边际收益。此次实测尚未接入完整比赛基线，不能称为新增 4,955 个记录。

完整读取时采用 HTTP gzip，实际压缩传输 1,979,168 字节；与逻辑文本大小分别记录。Range 字节窗口与 gzip 传输采用各自的字节坐标，不混用 offset。详细结果见[来源探针汇总](../audit/source_probe_20261124.json)。

### 4.1 数据祖源会影响发现收益

为每项来源记录两个字段：`provider` 与 `origin_family`。例如某索引由 Arquivo 提供，但抓取祖源是 Internet Archive；UKWA/JISC 的相关数据也来自 IA。两份数据仍可能因时间范围、迁移和覆盖差异互补，真实收益通过 exact hostname-year 差集确认。

来源状态区分：仅元数据可读、样本字节可读、完整分片可读、已接基线测产、已完成证据核验。这样可以准确安排下一步：入口问题对应取样工作，日期问题对应证据复核，容量问题对应来源拓展。

### 4.2 高权重 TLD 和未知可注册域如何兼顾

TLD 权重只进入预计收益和正式 EED；它不证明站点语言。新可注册域数单列，使用固定版本的 Public Suffix List 作为覆盖统计口径，原始 hostname 仍是身份键。现代 PSL 也不是历史注册制度的完整重建。

来源选择先看有依据的未消费观察范围、取得条件与证据可成立性，再结合实际边际 EED/成本。当前不预设固定探索比例或对已读 2001 数据重抽样；只有明确材料与待判别问题后，才确定相应投入。

## 5. 研究先行：当前仍需判别的具体问题

本节取代此前立即开展三组来源实验的安排。本轮只查阅资料与源码；来源含义和成熟机制先于数据试测。完整来源说明见[研究复核后的方案](EVIDENCE_LED_REDESIGN.md)。

| 问题 | 已有明确依据 | 仍需补齐的知识 |
|---|---|---|
| 原有大源还有什么操作未完成 | 用户提供 IA/WebBase 主体近乎完成状态；索引与转换代码已有依据 | 逐版本、范围、记录角色与操作账本；不能预设正文引用未处理 |
| 公开抓取索引外是否有同期观察 | PANDORA 1997 业务模型；Kulturarw3 2000 原论文 | 实际保存批次、目标年字段与交付说明 |
| 同期文本能否提供独立候选 | Usenet 具体文件目录、W3C 目标月档案、arXiv 版本与批量契约 | 目标记录日期、实际 URL、已有消费范围和基线外增量；见流水线来源表 |
| IA 派生渠道是否提供不同材料 | UKWA、Arquivo 与 IA 的共同祖源及投影说明 | 先证明与已处理范围的具体差异，再处理交付及身份映射 |
| 离线原材料能否恢复准确对象 | Archive95 1996/1998 的原始映射与修复代码 | 被保存页面与外链角色、每组材料的日期依据 |
| 是否有门槛级供给 | 当前门槛与年度键定义；主体大源已近乎读完 | 可得、年份适格且未被消费的实际材料库存；当前尚未证明容量 |
| 如何减少证据读取 | ArchiveSpark 两阶段访问、pywb 局部读取和 revisit 处理；CDX 源码明确相邻折叠与读取/输出上限区别 | 按 exact host 缺年选择 witness，校验实际捕获年；只在明确的索引范围完整消费后记录 no_match |
| 全球执行如何恢复 | Temporal Task Queue、Activity heartbeat/retry、Claim Check | 数据位置、来源主采集区和批次契约；框架不替代 HTTP 预算 |

当某问题经过说明与生成代码仍无法回答时，才定义有区分力的有限核验：明确候选解释、观察范围、预期差异及其对选型的影响。完整且语义明确的来源最终以年度差集量化贡献；该集合计算不能由文献推断，但也不应在来源身份未明时先跑出一个产率。

## 6. 最小工程组成与既有代码复用

首轮单机即可组织四项功能：来源读取、全局去重/基线差集、证据/进度记录、确定性导出。GPU 不进入这条批量文本处理链。容量按分片、外部排序和流式归并管理；当前六年 TXT 总大小约 2.90 GB，避免把所有行及其对象同时装入 Python set。

| 功能 | 优先复用 | 本次必要适配 |
|---|---|---|
| 基线成员查询与年度位图 | 旧 Creeper `authority/baseline_index.py` | 换为当前基线、权重和规则指纹；顺序任务也可直接合并排序年表 |
| CDX/CDXJ 解析 | 旧 Creeper `sources/archive/cdx.py`、`cdxj.py` | 保留 original hostname；解析出的年份和状态再次经过证据策略 |
| 年份聚合与 witness | 旧 Creeper `sources/archive/host_year.py` | 连续组压缩后加全局去重；保留候选 witness 替代路径 |
| 读取 ARC/WARC | pywb CDX/ZipNum、BlockArcWarcRecordLoader/ResolvingLoader、warcio；建索引用 cdxj-indexer | 采用元数据先筛和局部读取；本次身份/时间与复用 payload 分离 |
| 精确 EED | 当前仓库 `audit/audit_baseline.py` 与旧 `authority/eed.py` | Decimal/整数化权重；只对合格全局唯一差集汇总 |
| 批次恢复与进度 | Temporal Activity heartbeat/retry、外部不可变 manifest | 结果块先持久化；幂等导入后业务完成；来源 HTTP 预算独立管理 |
| 大批量排序/连接 | 外部排序与流式归并；需要时用 DuckDB | 按年或分片物化；性能不足再增加处理资源 |

旧仓库版本固定为 `9905a1897cb4e07fc2906cde68978449b7027659`。其 README 仍采用旧 5% 门槛和 ZIP 包装；本次按 1%/建议 2% 与 7z/Word 要求重新绑定。已读解析层对 2xx/3xx 及缺失状态较宽松，应经过新的证据策略；这项观察不等于已经证明旧系统最终会错误验收。[M9]

ArchiveSpark/ARCH 提供元数据优先、按需富化和原始链接抽取机制；是否采用其完整 Spark 运行时由已取得资料的处理需要决定。当前先固定来源与接口，原文定位和解析直接复用成熟组件。[M4、M5]

## 7. Agent 应承担的工作

Agent 的有效单位是来源家族、数据说明和可复用解析规则：寻找独立资料、检查年份语义、读取未知格式、提出适配器、解释失败与产率变化。确定性执行器处理每条数据、去重、证据状态和计分。

LLM 输出用于形成可验证的检索/解析建议；真实年度记录仍来自历史资料。早期方案采用“实测边际 EED/成本 + 探索预算”的透明调度。积累了多轮来源反馈后，再评估更复杂的序贯决策算法是否改善终端收益。

以下是下一步实现应建立的逻辑资产；任务包路径由调用者显式提供，沿用本地比赛数据位置。

| 位置 | 内容 | 复用方式 |
|---|---|---|
| `config/competition.json` | 规则/基线/权重版本与核心年度 | 每次试验和导出共同引用 |

## 9. 推进顺序与完成依据

1. **建立剩余材料依据。** 关闭 IA/WebBase 主体的重复优先级，补已处理范围账本；优先取得 PANDORA 目标年业务目录、独立国家采集/交存的生产与保存清单。没有实际材料的路线不进入容量预算。
2. **绑定竞赛材料与证据策略。** 在完整任务包所在位置核对基线、模型和 Contributor 说明；按来源类型写清身份、年份和网站语义，保留未定边界。
3. **按材料固定成熟组件接口。** 图读取器、pywb/warcio、年度位图和外排承接确定的数据操作；MemGator/MementoMap 可辅助定向补证；Temporal 承接有界批次。默认身份归并、来源和年份压缩按源码审计修正。
4. **对残余问题作有限判别，再执行确定任务。** 观察必须能改变来源或实现选择。来源、证据与基线明确后，才计算真实增量与剩余可取得范围。
5. **按瓶颈扩大，并形成完整提交。** 归并到最新基线下至少 1%，材料齐备后准备首批提交；2% 为后续目标。全球节点优先服务不同来源与就近数据处理。
6. **同步保留开放问题资产。** 前 1996 年材料与年份判定研究分别保存真实证据、方法和限制，扩展年独立列账。

每阶段完成依据是具体的说明、代码边界、可追溯资料和确定集合。尚无来源容量证明时，明确写未定，不用假设新增率推出确定完成日期。

## 11. 容量与全球执行的后续设计

[门槛估算与全球分布执行](CAPACITY_AND_GLOBAL_EXECUTION.md)把本方案的 1% 门槛进一步换算为候选数量、每请求收益和完成时间，并规定全球节点的任务所有权、共享来源预算、不可变输出及精确归并。采用一个逻辑控制面与多地执行器，按来源可达性分派网络操作，按资料位置分派批处理。扩容前先区分来源供给、访问预算、解析能力与证据验证四种瓶颈。对应离线估算器可以用实测参数重算；当前产率与吞吐仍是明确标注的情景。
