# 两个开放研究问题

本文件将任务书 IV-A 的问题转为可执行的研究定义，分别说明已有依据和待验证环节。它是研究方案，不是正式参赛包要求的 `Open Research Questions.docx`，也不宣称已经获得新的可验收域名增量。

## 问题一：怎样规模化发现并恢复 1996 年以前的历史网页资料

**对象。** 能够追溯到 1996 年以前的网页、服务器目录、网站备份、研究资料、软件发行介质和机构档案；仅有早期 DNS 或邮件主机名的资料属于发现层。最终需要恢复的是有明确时间语义和确切 hostname 的网站证据，而不仅是“看起来古老”的名字。

**研究假设。** 机构保存的网页目录、原始备份及其相关档案可提供通用网页索引以外的早期资料；沿保管机构、历史链接、研究引用和介质目录扩展，可能形成可批量处理的来源家族。该规模化收益假设尚待检验。

### 本次已做的公开入口核查

2026-11-24 检查了以下机构页面：

| 入口 | 可确认的事实 | 尚不能据此确认的事项 |
|---|---|---|
| [W3C 历史时间线](https://www.w3.org/History.html) | 页面明确指向 1992-11-03 的 WWW 项目快照及当时服务器列表 | 不能推出目录所有现代导航链接都来自 1992 年 |
| [W3C 保存的服务器目录](https://www.w3.org/History/19921103-hypertext/hypertext/DataSources/WWW/Servers.html) | 能读取历史目录正文、服务器链接及实验服务说明 | 尚未逐条核定链接协议、原始主机名、后加内容边界和可计分性 |
| [W3C WWW 历史入口](https://www.w3.org/WWW/) | 页面说明许多历史文档来自 1992—1995 年 | 该说明不是任意链接的逐条年证据 |
| [CERN 的 Web 起源页面](https://home.cern/science/computing/the-birth-of-the-web) | 说明 CERN 在 2013 年启动首个网站恢复项目 | 恢复时间不能当作原始内容时间；仍需底层副本与版本信息 |

这里完成的是入口和页面内容核查，没有完成批量下载、授权评估或新增记录验收。W3C 服务器目录同时存在后来的导航链接、FTP 超文本条目和实验服务描述；这说明解析必须识别历史正文边界与服务类型，不能把整页所有 href 自动记入 1992 年年度表。

### 建议试验（Pending validation）

1. **建立来源清单。** 先覆盖 W3C/CERN 历史目录、机构备份/软件介质、同期可信网页目录三类。逐项记录保管机构、访问入口、版本、覆盖时期、许可和批量取得方式；没有实际访问的来源标注未测试。
2. **冻结小样本。** 每类取一个明确版本或固定数量的资料项；保存下载时间、原始与恢复地址、文件哈希、记录定位。原始网页时间、备份时间、出版时间和恢复时间分字段存储。
3. **解析与人工对照。** 提取 hostname、协议和时间线索；对正文与后加导航分区；由固定样本核查确切形式、OCR 错误和年份语义。没有充分网站证据的条目留在候选层。
4. **验证批量可行性。** 检查是否有目录、数据包、清单/API 或可授权导出的索引；测量下载量、解析成本和有效证据产出。有限的演示页面不能证明可规模化恢复。
5. **作出扩大或停止决定。** 报告资料覆盖、有效 hostname-year、基线外增量、EED、人工审核分钟数、失败原因与访问限制。仅因一种版本收益低，不判整个来源家族无价值。

对 1996 年以前的合格记录，按规则放入 `extended_years/YYYY.txt` 并独立计算；不得填入核心六年。缺少适用扩展基线时只报告数量和加权总量，不自称获得官方百分比分数。

## 问题二：怎样更准确地判定网站在哪些年份存在

**对象。** 对每个 `(hostname, year)` 进行证据判定，区分“已证明网站出现”“只有发现线索”“检索尚未完成”“在某一检索范围内未命中”。目标是提高年度归属准确性，同时保持足够的新增覆盖和可承受的验证成本。

**关键不可识别性。** 没有 CDX 结果可能由未抓取、索引覆盖、访问限制、查询失败或真实无网站等多种原因造成。单凭未命中无法区分这些解释。首次观测时间也只给出已观测事实，不能证明此前没有网站或此后连续存在。

**建议机制（Pending validation）。** 将证据存为带时间和来源语义的图或关系表：hostname 连接到捕获/目录记录，记录连接到来源版本、时间字段和文件定位。自动规则只在确切 h、目标 y、网站语义和可追溯性同时成立时开放年度导出；弱线索用于排序核验任务。机器学习的置信度可以辅助排队，不得直接替代合格证据。

| 输入情形 | 年度判定 | 后续动作 |
|---|---|---|
| h 的 1997 年合格网页捕获 | 可支持 `(h,1997)` | 不外推至 1996 或 1998 年 |
| 父域或另一种 www 形式有 1997 年记录 | 不支持当前 h | 保存关联线索，核查当前确切形式 |
| 1996 年 ISC DNS 观测 | DNS 候选 | 找同年网站、目录或链接图证据 |
| 注册于 1996 年，2026 年仍可解析 | 无法仅据此判定历史网站年度 | 保留注册线索，逐年核验 |
| 查询限流、超时或分页不完整 | 未完成 | 恢复检查点并重试 |
| 查询成功完成但无结果 | 指定范围未命中 | 保留来源边界，可查其他证据 |

### 能区分方法优劣的验证设计（Pending validation）

建立按来源类型、年份、裸域/子域、是否已进入基线分层的固定样本，并保留未命中与错误记录。用独立证据复核形成可审计参考集，不能把同一套规则输出反过来当真值。

比较“仅用当前候选文本/最早年份推断”的诊断基线与“逐条证据判定”方法。前者只用于暴露错误传播，不生成正式年度文件。测量错误年归属、错误 hostname 归属、证据可复核率、未决比例、新增 EED 与单位验证成本。召回率只能相对于明确构建的参考集报告，不能外推全网。

单独设计故障恢复检查：同一批查询出现临时错误后，验证状态不会变成不存在；完成重试后，结果与正常运行一致。再做重复合并检查：同一证据重复输入不增加 EED，多来源命中只保留一个 hostname-year 贡献，候选转入某一年不会自动填充其他年份。

既有 ISC 报告的 `48/1800` 只能说明其抽样记录在 1996—2013 窗口内的 CDX 命中情况，未满足同年和成功网页内容的联合检验。本次据此设计验证层，未把该比例当作新方案的准确率。[S7 §4—9]

每个问题都应提供来源与访问路径、可运行步骤、固定样本、观测结果、失败日志、限制和下一步。正式参赛时还须按任务书提交对应 Word 文件及支持材料；未执行的步骤继续标记 `Pending validation`。当前文档中的可行性证据仅到已核查公开入口与本地规则/代码分析这一层。
