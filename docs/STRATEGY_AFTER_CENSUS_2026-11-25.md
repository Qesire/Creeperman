# 真实 census 后的策略重排（2026-11-25）

> 后续全量交集与配对查询中止结果已改变容量及执行优先级。当前以 [交集与中止试验后的竞赛策略](STRATEGY_AFTER_INTERSECTION_2026-11-25.md) 为准；本文件保留原有分析历史。

依据冻结提交 [391e229](https://github.com/Qesire/Creeperman/commit/391e22936eda068e3b14e8790ce9f8a1e5768e8f) 的 [实际 census](../audit/local_census_2026-11-25.json) 和 [本地报告](LOCAL_CENSUS_2026-11-25.md)，以及此前规则与 ISC 实验审计。本文件给出新的优先级，不修改原始统计、代码或竞赛证据规则。本轮为报告重算、史料调查与规划；未执行候选查询、下载、生产部署或正式提交。

## 1. 已得到的认识

- 89,165,782 个候选 host 中，88,352,433 个在旧池中（99.0878%）；联合集合比旧池多 813,349 个，但其中 714,541 个已在核心年基线，真正同时不在两者中的是 98,808 个。仅依靠这些新 hostname，六年、权重均为 1 的极乐观上界也只有 592,848 EED，不足以达标。这不限制旧池转化、已知 host 补年、新源增量。
- 全部缺年条件上界 266,735,784.5626 EED 不是历史网站库存。带年份提示的 17,379,306 个缺年中，17,379,074 个为 DNS-only（99.998665%），232 个为网页材料。Web 材料已结算 18 条 / 11.5612 EED，余 214 条 / 条件上界 173.2848 EED。
- WebKB 9,984 个唯一 host、220 个带年线索缺口；6 条本地核实；不能把 6/220 当最终验真率。Linux Gazette 168 个 host、12 个同年缺口，12 个均本地核实、5.731 EED，证明可信日期目录可直接走证据裁决（具体依据仍须逐条可回查）。二者的采集与处理时间未提供，不能据此计算 EED/hour。
- WebKB 的 1996 年 6 条据报告取原件 HTTP response Date，区别于 1997 年 1 月集合说明。保留本地已核实结论，同时在正式交付前检查 Date 的实际角色、缓存/原响应、来源 locator；不由集合日期覆盖原始证据，也不把 Last-Modified 当抓取时间。
- DNS 提示只集中在 1996/97；1998–2001 缺乏提示不是无剩余，而是当前资料投影缺失。旧池 8,835 万个名字没有逐条年份，应追索其生成账本，恢复真实 observation role/date，而不是假定原本没有相关数据。

## 2. 定量门槛与停止规则

剩余最低 EED（四位小数）= 764,304.4645 - 11.5612 = 764,292.9033。ISC DNS-only 目标 17,379,074 个，权重总和 8,845,163.0542，均权 0.5089548。单靠这些目标须兑现加权比例 8.6408%，即便每个命中权重均为 1，也至少需要 4.3978% 的目标键。1996 或 1997 单年分别需要 19.6182%、15.4424% 的加权兑现。

既有 ISC 报告 48/1800 = 2.6667% 测的是 1996–2013 任一年 CDX 命中且不限状态。若把该比例作为情景转移到当前 DNS-only 总体，并假设成功项均权不变，约 235,871 EED；即使成功项均权 1，也只约 463,442。抽样代表性未知，不能称其为当前总体估计或严格上界，但足以拒绝把无差别 CDX 遍历作为默认主线。

假设 30 天持续 0.4 req/s 或 4 req/s（均非服务承诺），分别只有 1,036,800 或 10,368,000 请求，须 0.737165 或 0.073717 EED/request。每次请求仅服务单个年度键、均权 0.509 情景下，前者即使全部命中也不够。全部 DNS 键一次查询的耗时分别约 503 或 50.3 天，未计重试/回放等。

对每一证据路线 j，登记剩余唯一目标集合 S_j、成本向量 c_j 和加权兑现率 q_j。以跨源全局精确差集结算，不能相加重叠上界。计划时间 H 秒与实际请求预算 R_e 需满足 sum_j requests_je <= H*R_e；各操作的真实边际 EED/request 包含未命中、错误、分页、补证。若全库存乐观可兑现贡献或预算上界仍不足，则转向新证据源。禁止以多 IP 绕开共享限额。

## 3. 首要路线：从观察供应出发，而非候选数量

优先历史 HTTP 调查、原抓取索引/图、具有明确日期及站点目录语义的机构清单、保存原件和原 URL 映射。它们可同时完成发现和相当部分举证。优先追溯真实文件、权限及与已读 IA/WebBase 的关系，原始采集家族而非托管者决定祖源。

### 3.1 大规模历史 HTTP 观测（最高优先调查）

- Netcraft [2000 年 7 月报告](https://www.netcraft.com/blog/july-2000-web-server-survey)明确称 2000 年 6 月普通 hostname 调查约 1700 万，active-site 方法约 750 万；每月发送 HTTP 请求；active-site 对同 IP 内容结构归并并对巨大站群抽样，与竞赛 exact hostname 规则不同。[1996 年 12 月](https://www.netcraft.com/blog/december-1996-web-server-survey)、[1997 年 6 月](https://www.netcraft.com/blog/june-1997-web-server-survey)、[1999 年 1 月](https://www.netcraft.com/blog/january-1999-we-server-survey)的报告保留了当年响应站点链接清单/交互查询的说明。现代 [Internet Data & Research](https://www.netcraft.com/solutions/other-solutions/internet-data-research) 支持定制数据/导出。新任务是核查当年站点列表快照及行级 HTTP survey 的可交付范围：exact hostname、观测月/日期、成功响应/服务器类型、原件或可信记录定位、许可、价格与实际基线重叠。汇总数字不是可下载库存；现未获取行级数据、报价、授权；未经用户要求不联系或购买。也不要把 active-site 数当 exact host 数。
- Bharat et al., ICDM 2001, [Who Links to Whom](https://people.csail.mit.edu/ruhl/papers/2001-icdm.pdf)，Table 2：Google 1999-10、2000-08、2001-06 三套 hostgraph 节点分别约 3.9M、10.4M、12.8M；保留了跨 host 关系概念，但这些是论文统计，不代表已找到公开原始表。询证保存的原始 hostname 字典、节点/出边角色、时间及授权。不要把 Google 图与 LAW WebBase 图混为一谈。PDF 文本可读，截图接口缓存失败。
- Shkapenyuk & Suel, ICDE 2002, [PolyBot 论文](https://research.engineering.nyu.edu/~suel/papers/crawl.pdf)，§4：约 500 万 host、1.2 亿网页级抓取，文中展示 2001-05-28 运行数据。优先查实际历史抓取批次、日志或 URL 清单留存及可得性；不是已获得的数据源。PDF 文本可读，截图接口缓存失败。
- 1996–2001 的访问日志亦属于不同观察机制，但仅考虑经许可、明确保留目标 hostname、日期、HTTP 状态等字段的去个人化聚合记录；不恢复匿名客户端/URL。DEC 1996 traces [发布说明](https://www.comp.nus.edu.sg/~cs5222/simulator/traces/digital/traces/tracelistv1.2.html)明确对 server name 和 URL 进行不可用原始映射的匿名处理、禁止还原，故关闭该对象；[Berkeley HTTP traces](https://zenodo.org/records/3749536)同样匿名化 URL，不作为 exact host 源。避免被请求规模误导。

### 3.2 可信目录与独立原件（可并行，短周转）

Linux Gazette 的 12/12 说明规则适格的同期站点目录能直接增加年度键，而无须逐条打 CDX。按“真实维护/分发清单”组织来源族：项目镜像目录的同期版本、公共服务目录、机构网站目录、历史互联网年鉴/光盘/软件分发目录、托管服务商的公开站点索引。必须核定每项究竟是 WWW 站点、FTP 镜像、邮件还是普通提及，不能将所有 URL 当网站证据。先批量抽取一个明确版本/覆盖范围、去重求差，再核算 EED/资料与剩余可获取版本；相同旧文件或同源镜像不重复算库存。Usenet/W3C/论文只在有明确网址或实体线索时作辅助，不为了增加名字重做 89M 池。

## 4. 用现有资产压缩验证空间（本地 Agent 第一项任务）

不重新全量 census。基于现有 opportunities、ISC 文件、候选池及年度清单，补做精确 host 与年度的关联。若机会文件/索引未保留，则一次排序归并生成分片或建立持久只读年度 bitmap。

A. 恢复旧池来源谱系：检查 Contributor_Data_Source_and_Methods_Summary_20261003.md、历史导入文件、原件和脚本；标注旧池中哪个名称来自实际网页、URL 目录、DNS 等，恢复真实年份提示及 locator。当前 0 提示只是现有输入的表示。
B. 对 DNS-only 17.38M 分层（互斥并可计算规模）：同年有真实网站观察直接裁决；同一 host 有其他核心年合格网站记录；同一 host 在 2002/03 辅助名单出现且名单具有可核实网站语义；仅同期明确导航/站点名称提示（不含纯邮件、资源）；剩余 DNS-only。优先 exact hostname 交集，禁止猜子域。按 y/TLD/权重、来源角色以及不同可注册域簇报告各层 N、总权重 W、重叠和可取材料。启发式 hostname 类别（www 等、邮件/拨号/路由）只用作优先级，不能硬排除。
C. 2002/03 两年辅助名单共 58,394,577 个物理行、约 1.49GB，先核来源许可、真实年份与角色、排序。仅对候选做本地匹配；如果它们确是历史网站集合，可用于判断时间近邻是否富集，不回填 2001 或更早；可能产生幸存者/来源偏差，必须与同年同 TLD 对照。不要一开始扫描全部 745M 辅助行。恢复到原始记录时应优先批量取 locator 而非逐 host 网络。
D. ISC mixed 原清单 461,629 行，拒绝 308,911（66.92%）。仅检查原始 schema、分隔/字段与日期角色，若能恢复 exact hostname 与实际年代则重导；不要为降低拒绝率放宽规则。

## 5. 最少量有区分力的后续实测

先完成 4A/B 的库存与角色表；若相应分层有可观剩余权重，才启动验证。既有 214 条网页候选用本地 witness 尽量结算；不重复核验 18 条已审记录。后续随机样本应基于固定种子在互斥层内抽样，分层配对 TLD、年份及可注册域簇；保留真实抽样分母。目的只回答：真实网页/相邻年份线索是否将同年合格 EED/request 提升至足以规划目标，是否有足够库存。第一批可在预算允许时比较每层 200 个目标（少于 200 则全取，避免多层无限增量）；这不是固定的科研样本量承诺，按目标精度与有效独立簇数调整。完整离线 lookup/已有 locator 优先；同馆已读索引范围不重查。在线端点仅对未解决且有依据的目标使用固定有限查询预算。报告 all attempted / index hit / exact same-year qualified / unresolved / total actual requests / unique new EED 以及同源重复。不把查询错误当负样本，不把空结果当全局不存在。不以最优子组向全体外推。

对各层 g，N_g、W_g 是已知；q_g 的加权区间从实际裁决得出（不确定/截断给保守范围，考虑可注册域聚类）。给定期限和授权预算，选择可兑现贡献大的层；若连乐观置信界或容量上界都无法支撑需要的贡献，则停止该层扩容。小型高收益资料不因总量小而关闭，但不替代规模级新来源。

## 6. 调度与交付

保留 Temporal/S3 架构，暂缓增加全球 Collector。当前真正瓶颈是证据供应与转化率；通过已有 provider 受控预算跑有限任务，扩大不同来源的获取能力和就近解析。v0.2 route-plan 默认先有提示、再按 hostname 文件顺序，实际上会被 ISC 淹没；改由上述分层表生成有依据的 online-plan，并把来源批次/证据角色纳入成本统计。优先级为 P0 现存资产证据连接、P0 Netcraft/独立历史 HTTP 调查/图的真实材料绑定、P1 同期权威目录、P2 定向在线剩余补证和语义反搜、P3 按实际瓶颈扩容。没有已取得的新供给则不得将百万级历史数据写为可用库存。

下轮本地交付 3 张表：候选分层及 N/W；历史观测文件/覆盖账本（已取得、可交付待定、关闭）；有限验证的实际边际 EED/cost 和可兑现容量。在此之前不重跑全池、不盲目抓取、不使用纯 DNS 证明网站，不宣布已达到 1%。正式参赛仍采用同年独立证据、最新基线和任务包计算器。
